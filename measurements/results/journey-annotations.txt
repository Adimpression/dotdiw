Journey annotations -- dotdiw 4.2.2

Scope
- All 55 governed operations retain their native IDs and 12 source journeys.
- 128 declarations in dotdiw carry literal journey tags: operation bodies,
  registered adapter operations and extras, provider entry points, dedicated
  helpers (including class methods), and operation presenters.
- promise_bindings.py contains 77 explicit generated callables. Their public
  names, request signatures, lazy loading, operation routes and body/adapter
  metadata are retained. Each marker returns the original callable.
- All 11 Jira operations and 11 generated tracker-starter operations carry
  their native journey IDs. Shared infrastructure acquires no invented journey.
- Native conformance checks the 66 canonical implementation bindings and the
  11 direct Jira bindings in poa/journey-bindings.json: 77 declarations total.
- Tags declare lineage. Behavioral tests and CESC evidence establish separate
  facts; a tagged starter still refuses an unimplemented operation.

Verification boundaries
- Native POA derivation supplies every operation semantic section unchanged.
  The existing derivation test then applies all project manifests in memory
  and compares the complete result with the submitted operation-idl.json.
- Generated tables, record types, starter text and binding declarations are
  compared with the submitted IDL without rewriting the checkout. Regeneration
  belongs to the formula's generate step, not its root verification commands.
- Disposable stale-manifest and stale-IDL fixtures fail the full comparison.
  Removing NameTheWork's binding tag fails freshness without repairing it.
  Submitted-file digests remain unchanged through each verification.
- Negative native annotation tests require the exact implementation locator,
  operation ID, diagnostic code and journey ID. Unrelated diagnostics cannot
  satisfy them; the former last-operation-tag false positive is covered.
- The promise formula pours all 15 steps under Jira's 255-character summary
  limit and retains every verification instruction on the root. The stub
  enforces the limit for issue creation and field updates.
- The existing request-boundary mutation targets the explicit MatchFormulas
  binding. Thirteen additional mutations cover tags and declaration generation.
  There are 964 mutations in the complete table.
